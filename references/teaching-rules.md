# 教学规则 · Teaching rules

本文件规定「怎样把看不懂的材料讲成能看懂的」。每条规则后面标注来源：
`[tutor]` = scientific-literature-tutor，`[learning]` = UiB 学习总纲与六篇精读页，`[reader]` = nature-reader。

## 1. 先判断读者起点，再决定从哪里讲起 `[learning]`

- 先问（或从上下文推断）读者对这份材料的基础是什么，写进规格的 `reader.starting_point`。
- 列出读懂本材料必须先有的前置概念，写进 `reader.prerequisites`，并标注在哪个单元补。
- 零基础读者先讲背景，再读正文；不为赶进度跳过前置知识。
- 一次只推进一个核心概念；读者回答检查题后再推进下一个。
- 如果讲解中暴露出新的前置知识缺口，暂停当前单元，插入一个更基础的微型单元，原位置记下「返回点」。

## 2. 证据地图先于写作 `[tutor]` `[reader]`

写任何讲解之前，先通读全文并建立私有的工作地图：

- 学术研究类（paper / 研究计划 / 实验报告）：`question`、`hypothesis`、`samples`（真正的独立单位）、`X`、`Y`、`model`、`validation`（留出的单位、泄漏风险、指标、有无外部验证）、`claims`（哪张图支持哪个主张）、`limits`。
- 非研究类（合同、政策、课程材料、商业报告）：逐段标出「主张 — 依据 — 边界」，再找出全文的论证骨架（背景 → 空白/问题 → 提议 → 依据 → 条件/例外 → 边界）。
- 把材料里的说法当作「主张」，不自动当作事实。
- 永远不要把「数据怎么造出来的」称作「验证」。构造与验证是两个阶段。

## 3. 每个单元的固定结构 `[learning]`

每个单元只处理一个概念，约 25 分钟。推荐顺序（尤其是第一单元）：

1. 为什么要关心这个问题
2. 主角是谁（核心对象、术语第一次出现时翻译）
3. 难点在哪
4. 作者 / 材料的想法是什么
5. 本课术语

每个单元末尾固定有：

- **检查题**：不用术语，几句话能答；读者答完才算过关。
- **答疑记录**：读者的提问和讲解写回页面对应位置，标为「答疑 N」；只记录结论，不复制整段聊天。

## 4. 每张图 / 每个证据块的固定七字段 `[tutor]`

对每张主图（或非论文材料中的每个关键表格、条款、数据块）都按同一逻辑讲：

1. 本图回答什么 / Question
2. 数据怎么来 / Data provenance
3. 图怎么读 / Reading guide（面板、坐标轴、颜色、符号、单位、样本对应）
4. 看到了什么 / Observation（只写看得见的，不过度解释）
5. 作者主张什么 / Claim
6. 不能证明什么 / Limitation
7. 术语 / Glossary

每张图先给一句「先记一句」的要点，再展开。可以加小型教学示意图或数字例子，但不能用流程图替代原图。

## 5. 七问卡片与两栏判决 `[learning]`

每篇研究类材料都要填同一张七问卡片，方便跨材料比较：

| 问 | 写什么 |
|---|---|
| 研究问题 | 一句话 |
| X | 输入是什么、从哪来、怎样汇总 |
| Y | 目标是什么、怎样测、什么时候测 |
| 独立样本是谁 | 名义样本数 vs 真正独立的单位 |
| 怎样验证 | 模型、留出的单位、指标 |
| 能证明 | 在这些条件下成立的结论 |
| 不能证明 | 设计无法支持的推广 |

非研究类材料改用「主张 — 依据 — 边界」表，每行带原文位置。

两栏判决（`verdict`）：左栏「材料支持」，右栏「材料没有证明」。两栏都要写，不为了让材料显得干净而隐藏弱点。

## 6. 审计并用克制的措辞 `[tutor]`

讲解的同时明确标出：

- 名义样本数与独立单位数的差别（如 1,920 张照片 ≠ 1,920 个样本）；
- 生物学重复 vs 技术重复；缺失数据与失败的实验；
- 内部交叉验证 vs 留出的外部队列；按什么单位划分；泄漏风险；
- 基线是什么，指标有没有赢过基线；误差棒、多重比较、统计假设；
- 正文、表格、图注之间的矛盾；
- 资助、专利、商业化等可能影响解读的利益关系。

措辞：当材料没有建立因果或泛化时，用「支持」「与……一致」「提示」，不用「证明」「表明……必然」。

## 7. 语言与术语 `[tutor]` `[reader]`

- 默认中文讲解，关键英文术语在第一次出现时翻译，之后保留英文原词在括号或 `term` 标记中。
- 建立术语账本（Terminology Ledger）：一个概念只用一个名字，全页一致；缩写第一次出现时展开。
- 不给材料里的方法、模块、概念起新名字；材料没定义的术语，标注「原文未定义」。
- 数字、单位、符号、基因名、公式、引用标记保持原样。

## 8. 讲解风格 `[tutor]` `[learning]`

- 从材料想解决的问题讲起，不从软件或实验步骤讲起。
- 用具体映射，例如「早期形态 X → 数周后的分化能力 Y」。
- 每张图、每个单元先给一句要点，再加细节。
- 适当用比喻（`analogy` 块），但比喻之后要回到原文。
- 邀请读者按图、按面板、按段落提问，例如「Figure 3C 为什么要除以 pellet size？」。
- 不隐藏弱点：理解弱点是理解材料的一部分。

## 9. 回答读者提问时 `[reader]` `[learning]`

1. 先找最相关的原文块，从原文回答；
2. 给出页码 / 段落 / 图注等锚点；
3. 材料没说的，明确写「原文未说明」，不编；
4. 答完后明确写出下一步：继续当前单元、补前置知识，还是返回原问题；
5. 把答疑写回页面的 `qa` 字段，并在问题索引里记一行摘要。
