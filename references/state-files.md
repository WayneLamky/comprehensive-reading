# 三层学习状态文件（可选） `[learning]`

长对话容易把讲解、追问和临时解释混在一起。UiB 学习项目用三层文件解决：稳定的总纲、短小的当前状态、只记摘要的问题索引。恢复学习时先读前两个文件，需要时才按编号查第三个。

## 文件与职责

| 文件 | 内容 | 改动频率 |
|---|---|---|
| `00_总纲.md` | 最终要学会什么、单元路线、每单元的过关标准、提问规则、上下文控制协议 | 低 |
| `01_当前状态.md` | 当前单元、今天唯一目标、待回答的检查题、已掌握、仍模糊、当前返回点、下一步；控制在约 120 行 | 每完成一个单元更新一次 |
| `02_问题索引.md` | 每个问题一行：编号、一句话摘要、归属单元、状态、后续动作；不复制聊天 | 每次答疑追加一行 |

## 规则

1. 不把原始对话逐字保存；不把临时解释提升为长期结论。
2. 普通追问不重写总纲。
3. 每次对话开场只说三件事：当前单元、今天唯一目标、上次停在哪里。
4. 每次对话收尾只记四件事：已掌握、仍模糊、当前返回点、下一步。
5. 读者可随时提问。与当前概念直接相关：立即讲清再回到原问题；暴露前置缺口：插入微型基础课，完成后返回；属于后续章节：先给一句必要答案，记入问题索引。

## 模板

### `00_总纲.md`

```markdown
# <材料 / 课程名> 学习总纲
版本：<日期>
适用对象：<读者起点>
原则：先建立背景，再读正文；一次只推进一个核心概念；不为赶进度跳过前置知识。

## 一、最终要学会什么
1. …

## 二、单元路线
### U1｜<标题>
- 目标：…
- 过关：…

## 三、每个单元
讲解约 8 分钟 → 读者独立作答约 10 分钟 → 纠正补充约 5 分钟 → 写入状态约 2 分钟。

## 四、提问规则
（见上文规则 5）

## 五、上下文控制协议
（见上文规则 1–4）
```

### `01_当前状态.md`

# 当前学习状态
更新时间：<日期>

## 当前单元
- 材料：…
- 单元：U2｜…
- 状态：已讲解，等待读者回答检查题

## 今天唯一目标
…

## 检查题（待回答）
…（预期要点：…）

## 已掌握
- U1（<日期> 过关）：…

## 仍模糊
- …

## 当前返回点
- U2 回答后进入 U3 → U4 → …

## 已确认的学习需求
- 中文讲解，保留关键英文术语；每次只讲一个概念；可随时提问。

### `02_问题索引.md`

```markdown
# 学习问题索引
| 编号 | 问题摘要 | 归属 | 状态 | 后续动作 |
|---|---|---|---|---|
| Q001 | … | U1 | 已解决 | 写回页面答疑 1 |
```

## 与精读页的关系

- 页面里的 `units[].status` 与 `01_当前状态.md` 的「当前单元」保持一致。
- 页面里的 `qa` 与 `02_问题索引.md` 一一对应：索引记一行摘要，页面放完整讲解。
- 读者在页面上写的回答通过「导出我的问题」复制出来，或在 Artifact 评论里发送；老师回答后写回 `qa`，重新构建页面。
